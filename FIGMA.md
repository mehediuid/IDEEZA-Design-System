# Working in Figma

The Figma file is the source. This repo is a copy of it, generated by reading
values out with the plugin API — never retyped, never estimated. Everything
below follows from that one fact: a design decision is made in Figma, and the
repo's job is to be right about it.

So the first rule is the boring one. **If the code and the file disagree, find
out which is wrong before changing either.** Both directions happen. Five
classes in this repo named tokens that did not exist, so the code had been
silently wrong for months. The dark-mode Inverse button is white on white
because the *file* says so. Neither was found by looking; both were found by
checking.

---

## 1 · How the file is laid out

Three levels, numbered, grouped onto pages by what they do:

| Prefix | Level | Pages |
|---|---|---|
| `A01`–`A30` | Atoms | `Atoms — Input`, `Atoms — Display` |
| `M01`–`M51` | Molecules | `Molecules — Feedback`, `Molecules — Navigation` |
| `O01`–`O38` | Organisms | sections and heroes |

A number belongs to a component for good. `A17` is Badge and stays Badge even
if Badge is deleted — the numbers are how the repo, the docs and the review
notes point at things, and reusing one silently repoints all of them.

The current atom map, taken from the components themselves:

```
A01 Button          A11 Slider          A21 Skeleton
A02 Icon Button     A12 Number Input    A22 Progress Bar
A03 Link            A13 Color Picker    A23 Progress Ring
A04 Text Input      A14 Multi-select    A24 Divider
A05 Textarea        A15 Button Group    A25 KBD
A06 Select          A16 Avatar          A26 Dot
A07 Search          A16c Avatar Group   A27 Code
A08 Selection       A17 Badge           A28 Inline CTA
    Control         A18 Tag             A29 Brand Icon
A10 Toggle          A19 Tooltip         A30 Delta Chip
                    A20 Spinner
```

`A08 Selection Control` is one component holding both Checkbox and Radio. `A09`
is unused. Suffixed numbers (`A16c`, `A19b`) are parts that only exist to serve
their parent and are not used alone.

Molecules follow the same shape: `M01` Alert, `M02` Toast, `M03` Banner, `M04`
Snackbar, `M05` Inline Message, `M06` Status Block, `M14` Tabs, `M16` Sidebar
Item, `M18` Dropdown Menu, `M19` Breadcrumb, `M20` Pagination, `M50` Loading,
`M51` Skeleton.

## 2 · The values, and where they come from

These are the whole vocabulary. A design that needs a number not on these lists
is either wrong or is proposing a change to the system — and the second one is
a conversation, not a layer property.

### Type

Manrope for everything, Roboto Mono for code. **Every piece of text goes
through a named style.** A layer with a hand-set size is the single most common
way this system rots, because it copies forward into every duplicate of that
frame and nothing catches it.

| Step | Desktop | Mobile |
|---|---|---|
| `2xs` | 10 / 14 | — |
| `xs` | 11 / 16 | — |
| `sm` | 12 / 18 | — |
| `md` | 14 / 20 | — |
| `lg` | 16 / 24 | — |
| `xl` | 18 / 26 | **16 / 24** |
| `2xl` | 20 / 28 | **18 / 26** |
| `3xl` | 24 / 30 | **20 / 28** |
| `4xl` | 28 / 32 | **24 / 28** |
| `5xl` | 32 / 36 | **28 / 32** |
| `6xl` | 48 / 40 | **36 / 36** |
| `7xl` | 60 / 56 | **44 / 42** |
| `8xl` | 72 / 68 | **52 / 50** |

Body steps (`2xs`–`lg`) do not change on mobile. Only display sizes come down,
because 72px does not fit a phone and 14px reads the same on both.

Weights: 400 regular, 500 medium, 600 semibold, 700 bold, 800 extrabold.

Letter-spacing only ever goes negative, and only on the display steps —
`slight` −0.25 through `tighter` −2.5. Big type needs tightening; small type
does not. The two positive steps exist for caps only (`caps` 1.5, `widest` 1.2).

### Space

`--spacing-1` is 2px and the scale counts in those: 1=2, 2=4, 3=6, 4=8, 5=10,
6=12, 7=14, 8=16, 10=20, 12=24, 16=32, 20=40, 24=48, 32=64, 40=80, 48=96.

Below 16px nothing changes on mobile — a 4px gap is a 4px gap on any screen.
From `10` up, everything compresses: 20→16, 24→20, 32→24, 40→32, 48→40, 64→56,
80→64, 96→80. Section rhythm shrinks on a phone; component padding does not.

### Radius

`xs` 2, `sm` 4, `md` 6, `lg` 8, `xl` 12, `2xl` 16, `3xl` 24, `full` 9999 —
and on mobile every step is drawn one notch softer (`xs` 4, `sm` 6, `md` 8,
`lg` 10, `xl` 14, `2xl` 18, `3xl` 28).

Radius follows size, not taste: the 32px control takes `lg`, and by 48px it is
at `2xl`. Pills are for things that are not controls — Badge, Tag, Dot.

### Colour

Three layers, and **a design never reaches past its layer**:

```
primitive     violet/600, gray/50, red/500          — the palette
   ↓
semantic      bg/*, text/*, border/*, icon/*        — what it means
   ↓
component     button/*, input/*, badge/*, tag/*     — where it is used
```

A layer filled with `violet/600` is a bug even when it is the right purple,
because rebranding then means finding every one of them. Fill with `bg/ai` and
the palette swap is one variable. (`A01 Hierarchy=AI` currently breaks this —
see §5.)

Everything is defined twice, light and dark, and **dark is not a filter over
light** — it is a second set of decisions. A colour added to one mode and not
the other is a component that vanishes for half the users.

Focus is a 3px halo, never a border: `focus/halo` normally, `halo-on-fill` over
a filled surface, `halo-danger`, `halo-ai`, `halo-inverse`. A border would
change the element's size and shift the layout every time someone tabs.

### Motion

**120ms, `ease-decelerate` (`cubic-bezier(0, 0, 0.2, 1)`).** This is the
interaction constant — 7,194 of the file's prototype reactions use it, and
every hover, press and state change in the system is that number. It is fast
enough to feel like a response rather than an animation.

The other durations are for things that are not interactions: `fast` 100 for
something already in motion, `normal` 200 for a panel, `slow` 300 for an
overlay, `slower` 500 for something entering the screen for the first time.

### Elevation and layering

Elevation is `0`–`6` plus `inner`, and means distance from the page, not
decoration — the geometry doubles at each step (1/2, 2/4, 4/8, 8/16, 12/24,
16/32). Two surfaces at the same distance get the same shadow.

**The opacities are completely different in dark mode**: 0.05→0.5 at step 1,
0.16→0.85 at step 6. A shadow that reads on white is invisible on near-black,
so dark mode is not the same shadow dimmed — it is roughly ten times the
opacity. This is why elevation must be picked as a token and never drawn by
hand.

Stacking order is fixed and non-negotiable, because the bugs it prevents are
the kind that only appear for one user on one screen: sticky 10, dropdown 1000,
overlay 1100, sheet 1200, modal 1300, popover 1400, toast 1500, notification
1600. A toast outranks a modal deliberately — you must be able to be told
something while a dialog is open.

### Touch

44px minimum, 48 comfortable, 56 large. A 32px control on a phone still needs
44px of tappable area around it; the control does not grow, the target does.

## 3 · Adding a component

In order. Steps 1 and 2 are where the work actually is.

1. **Justify it.** Which existing component is nearly this, and why is it not
   this? Most new components are a variant of something already drawn, and the
   library gets worse every time that answer is skipped. `Field` exists because
   six inputs shared a shell; `Search` exists because `A04` plus a fixed
   leading icon is a different thing to use, not a different thing to draw.
2. **Take the number.** Next free one at its level. Write the description while
   you have the reasoning in your head, not later.
3. **Build it from variables only.** No hand-set colour, size, radius or
   spacing. If the design needs a value that is not in §2, stop and decide
   whether the scale is wrong — that decision is worth more than the component.
4. **Every state.** Default, Hover, Active/Pressed, Focus, Disabled, and any
   Loading, Selected, Invalid the component can be in. **Disabled uses the
   disabled tokens, never layer opacity** — opacity fades the shadow and the
   border along with the label, and it looks like a rendering fault. There are
   43 variants in the file still doing this.
5. **Both themes.** Place it on a dark artboard and look at it.
6. **Prototype the interaction** at 120ms ease-out, so the repo can read the
   motion rather than be told it.
7. **Then the repo copies it** — `MIGRATION.md` has that side.

**Naming.** `A17 Badge`, then properties as `Size`, `Variant`, `State`, values
in the same words the props will use. `Size=MD` becomes `size="md"`. Renaming a
property later breaks every instance in the file and every consumer of the
package at once.

## 4 · What the code added, where the file is silent

Not defects. Decisions taken here because Figma cannot express them, listed so
they can be adopted or overruled rather than discovered.

- **Press, lift, swell.** The file specifies a 120ms cross-fade and nothing
  else. Anything clickable also compresses slightly on press; raised surfaces
  lift on hover; flat ones swell. Reasoning is in `Button.css`.
- **Skeleton shimmer.** The file has no motion on skeletons. A static grey
  block reads as a broken layout, so these pulse. `animate={false}` opts out.
- **Sliding tab indicator.** The file draws the active treatment on each tab.
  The code slides one element between them — identical at rest, different only
  in transit.
- **`Field`.** Not in the file at all. It is the label / control / helper shell
  that repeats across A04, A05, A06, A14 and the rest, and pulling it out is
  what stops those six drifting apart. **Drawing it in Figma would be the
  single most useful addition to the file** — right now the shared part is
  shared in the code and duplicated in the design, which is the wrong way
  round.

## 5 · Open, and provable from the repo

Each of these can be confirmed without opening Figma.

**The Inverse button disappears in dark mode.** In the dark block,
`bg/inverse` is `gray/50` — near white — while `button/inverse-bg` stays
`#ffffff` in both modes. An Inverse button on an inverse surface is white on
white. One of the two is wrong and it is a Figma decision which.

**`A01 Hierarchy=AI` fills with a primitive.** `bg/ai` resolves to
`violet/600` directly, skipping the semantic layer that every other hierarchy
goes through. A brand change has to be made twice.

**Border weight is mixed.** 1.5px on Text Input and Textarea, 1px on A06, A07,
A12, A13, A14 and `_OTP`. No layout shift either way, but two weights in one
form is visible.

**`A03 Link` SM has no named style.** It is set in an unnamed 12/16 Medium. The
nearest named style is Body/XS Medium at 12/18, which is what the code uses.
Per §2 it should become a style.

**`A29 Brand Icon` is placeholder geometry.** Not the real marks.
`packages/icons/src/brands/README.md` has the import procedure. Blocked on the
official assets deliberately — they are trademarks and redrawing them by hand
is not an option.

## 6 · Open, needs the file

The Figma MCP is not authorised in this environment, so these are unverified
rather than unimportant.

- **`A16 Avatar` focus ring.** The code draws the 3px halo like everything
  else. The file may still carry an older 2px ring.
- **Brand-coloured sections, `O25`–`O38`.** The halo sits on the page
  background, so Primary focus can wash out on a violet hero. Never reviewed.
- **The Atoms — Input audit.** Twelve of its thirteen findings are untouched:
  Hover missing across seven sets, the 43 opacity-hack Disabled variants,
  radius scale misalignment, `border/*` and `input/*` overlapping, five missing
  descriptions, prototype gaps, and no A-level OTP component.

## 7 · Closed — the file was right, the code was not

Kept because each of these looked fine on screen for months.

- `bg-bg-info-subtle` — Alert, Banner and StateView had no info background.
- `text-text-blue` — Badge's blue outline label had no colour.
- `text-icon-default` — IconButton and Input never applied their icon colour.
- `hover:text-text-brand-hover`, `hover:text-text-error-hover` — Link did not
  change colour on hover.
- `transition-[colors,box-shadow]` — `colors` is not a CSS property, so every
  input's border and background snapped instead of animating. Still present in
  Avatar, Checkbox and Radio, which have not migrated yet.
